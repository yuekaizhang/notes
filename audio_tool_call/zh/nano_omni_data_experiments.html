数据实验全景：一个原始池的七种切法 Data experiments: seven slices of one pool

所有训练集都来自同一个 1.4M 行的原始池。各实验只改两件事：用哪个模型给样本打难度分，以及按什么规则过滤或采样。结果表明这两件事实际是同一个旋钮：难度过滤会同时改变动作类型配比，而配比基本决定了训练结果。

Every training set is carved from the same 1.4M-row pool. Across experiments only two things change: which model scores sample difficulty, and the filtering or sampling rule. These turned out to be the same knob: difficulty filtering also shifts the action-type mix, and that mix largely decides the outcome.

03 机制：难度过滤为什么会剔掉 message Mechanism: why difficulty filtering strips out message rows

判分器对期望动作是 message 的行只检查"是否在说话"，不判内容，所以 message 行普遍高分、function_call 行普遍低分。任何"保留低分行"的过滤规则都会定向剔除 message；打分模型越准，剔得越干净。

For rows whose expected action is a message, the verifier only checks that the model said something — content is not judged. So message rows score high and function_call rows score low. Any "keep the low-scoring rows" rule therefore strips out message rows, and the more accurate the scoring model, the cleaner the strip.

05 结论 Conclusions

核心问题the central question

"score ≤ 0.6 的数据不能用"？只对了一半"Data scored ≤ 0.6 is unusable"? Half true

问题不在阈值，在谁打的分。nano 自己打分再取 ≤0.6，message 只剩 13–14%，相关的三个实验全部变差；换 Super3 或 Qwen3 打分，同样的 0.6 阈值，message 保住 29–32%，是仅有的两份能用的数据。在这个判分器下，"难度画像要用被训模型自己打"这条经验要反着用。

The threshold is not the problem — who does the scoring is. When nano scores itself and we keep ≤0.6, message rows drop to 13–14% and all three related arms get worse. With Super3 or Qwen3 doing the scoring, the same 0.6 threshold keeps message at 29–32%, and those are the only two usable sets. Under this verifier, the rule "difficulty profiles must come from the trained model itself" should be applied in reverse.

难度过滤和配比过滤是同一件事Difficulty filtering and mix filtering are the same operation

判分器给 message 行的平均分是 0.72，function_call 行是 0.17。按分数筛行，等于按动作类型筛行：被丢弃的行 76% 是 message，全零行 96% 是 function_call。所谓难度信号，大半是动作类型的影子。

The verifier gives message rows a mean score of 0.72 and function_call rows 0.17. Filtering by score is filtering by action type: 76% of dropped rows are messages, 96% of all-wrong rows are function calls. Much of the "difficulty" signal is a shadow of the action type.

message 占比 29–32% 是仅有的安全区A 29–32% message share is the only safe range

53%（不过滤）近中性，29–32% 不掉分，25% 开始变差，13–14% 崩坏。message 内部还分两种成分：混合得分的行教模型"该说话时别调工具"（v2 缺它，telecom 崩），天然全对的行稳住 airline（v1 缺它，airline 伤）。两种都要。

53% (unfiltered) is near neutral, 29–32% holds up, 25% starts to hurt, 13–14% collapses. The message rows also split into two roles: mixed-score rows teach "talk instead of calling a tool" (v2 lacked them and telecom collapsed); naturally all-correct rows stabilize airline (v1 lacked them and airline suffered). Both are needed.

转人工样本被富集，telecom 为此买单Transfer rows get enriched; telecom pays for it

转人工行得分低（0.16），难度过滤把它从 5% 富集到 10.5%，还是三个集合里出现最多的单个工具。训练后模型学会提前转人工：telecom t1 的转人工率从基座的 41% 升到 D4 的 66%、D6 的 79%（第 1 条消息就转），而 t1 的多故障排查题一转就输。

Transfer rows score low (0.16), so difficulty filtering enriches them from 5% to 10.5% — the single most frequent tool in all three filtered sets. The trained model learns to hand off early: transfer rates on telecom t1 go from 41% (base) to 66% (D4) to 79% (D6, often at the first message), and t1's multi-fault troubleshooting tasks are lost the moment the hand-off happens.

原始池本身有质量上限，约 52–53The raw pool has a quality ceiling around 52–53

D7 三个版本在原始池上把配比、难度、message 成分全部控制到位，仍停在 52–53；D2 能到 56。排除掉所有已测变量后，剩下的解释是 Super3 过滤顺带做了行级质量筛选。原始池上的配比类变量已经试完了。

The three D7 variants control mix, difficulty, and message composition on the raw pool and still stall at 52–53, while D2 reaches 56. With every measured variable ruled out, the remaining explanation is that the Super3 filter also performed row-level quality selection. The mix-related variables on the raw pool have been exhausted.

下一步：改判分器的 message 判分Next: fix how the verifier scores messages

画像混杂、DAPO 崩坏、message 行没有梯度（说话就满分，组内无方差），三件事的根源都是判分器不判 message 的内容。改掉它，难度分才第一次真正反映难度；不改，就回到 D2，数据侧到此定稿。

The confounded difficulty profiles, the DAPO collapse, and the missing gradient on message rows (full marks for any reply means zero within-group variance) all trace back to the verifier not judging message content. Fix that, and difficulty scores reflect difficulty for the first time; otherwise, return to D2 and close out the data track here.
